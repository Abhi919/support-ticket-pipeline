# Jira analysis rules

1. Treat the Jira ticket as the source of truth for scope; comments and attachments may refine it.
2. If using Jira MCP: fetch summary, description, acceptance criteria, labels, components, links, and recent comments.
3. Always restate **in your own words** what “done” means before proposing design.
4. Record **dependencies** (other tickets, teams, releases) in `context-analysis.md`.
