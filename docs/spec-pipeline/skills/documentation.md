# Skill — Documentation

When writing or updating spec artifacts and `implementation-notes.md`:

- Use clear headings and tables for AC/NFR/task IDs.
- Link related files (`requirements.md` ↔ `api-contract.md` ↔ `tasks.md`).
- For API docs, mirror `api-contract.md`; do not duplicate divergent descriptions in README.
- Record spec drift in `spec-diff.md`, not inline comments only.
- Keep prose concise; prefer numbered criteria over narrative walls of text.
